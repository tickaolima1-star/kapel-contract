# Memory Capture

## Description

Promote only durable repository knowledge into version-controlled documentation after work is verified.

## Steps

1. Review the completed work, debugging evidence, decisions, and corrections.
2. Keep only non-obvious business rules, expensive debugging discoveries, and repository constraints likely to recur.
3. Reject secrets, credentials, personal data, transient task narration, timestamps with no future value, and facts already obvious from code.
4. Choose the smallest existing target document; create a new focused document only when no suitable home exists.
5. Write the lesson as a concise rule with context, evidence, and the condition under which it applies.
6. Show the exact diff and verify that links and commands remain valid.
7. Commit memory separately when it is not required for the implementation itself.
